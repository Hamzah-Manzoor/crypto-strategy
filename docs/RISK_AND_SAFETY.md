# Risk and Safety

## The rules
1. **No real money.** The lab only runs **backtests** (replaying past prices) and **dry-runs** (live prices, fake 1000 USDT wallet).
2. **No API keys anywhere.** Not in configs, not in `.env`, not in Docker files, not in your shell environment.
3. **The safety check runs before anything starts,** and it can't be skipped by accident.
4. **No data, logs, databases or secrets in git.**

## Why no API keys at all?
- **Dry-run doesn't need them.** Freqtrade only reads public prices (candles and the order book) and simulates the trades itself.
- **A key that doesn't exist can't leak.** It can't be committed by mistake, stolen from a laptop backup, or used by a bug that flips a setting.
- **Freqtrade can trade for real with a single setting** (`dry_run: false`). With no key, even that mistake can't place an order.

## How the safety check works
`scripts/safety_check.py` fails loudly (big red banner, exit code 1) if it finds any of these:

| Check | Where it looks |
|---|---|
| `dry_run` is anything but `true` (and `base.json` must say `true` explicitly) | every config, plus base.json merged with each override |
| exchange `key` / `secret` / `password` / `uid` / `apiKey` / `privateKey` / … is filled in | every config's `exchange` section, including `ccxt_config` |
| `FREQTRADE__EXCHANGE__KEY`-style variables, or names like `BINANCE_API_KEY` | `.env*` files, compose files, current environment |
| `FREQTRADE__DRY_RUN` set to anything but true | `.env*`, compose files, environment |
| futures or margin (`trading_mode` other than `spot`) | configs and environment |
| FreqUI password / JWT / Telegram token written in a committed config | configs (these belong in `.env`) |
| a Docker port not bound to `127.0.0.1` | compose files (FreqUI must not be reachable from your network) |
| `trade` started without `--dry-run` | compose files |
| `.env` tracked by git | git index |

**It runs in three places:**
1. **`lab.py`** runs it before every command that starts Freqtrade.
2. **The `safety` service in `docker-compose.yml`.** Every Freqtrade container `depends_on` it. If you bypass `lab.py` and type `docker compose run …` yourself, Docker still refuses to start. Use `docker compose logs safety` to see why.
3. **The git pre-commit hook** (`scripts/hooks/pre-commit`). It blocks commits containing data, logs, databases, `.env` or files over 2 MB, then runs the safety check.

**A fourth layer for the bots:** the paper-trading bots run `freqtrade trade --dry-run`. That flag makes Freqtrade itself remove any exchange secrets and simulate trades, whatever the config says.

**Tested:** `tests/test_safety_check.py` has 31 cases. Each blocked situation above has a test that fails if the check misses it. Phase 2 also broke the real config by hand (set `dry_run: false`, put a fake secret in `.env`) and confirmed both `lab.py` and a raw `docker compose run` refused to start.

## Other safety settings
- **FreqUI is local only.** Ports are bound to `127.0.0.1`, so only this Mac can open it. The password, JWT secret and websocket token are random, generated by `lab.py setup` into `.env` (git-ignored, file mode 600).
- **Telegram alerts are off by default.** Turning them on needs a bot token in `.env` only. A Telegram token can read your bot's status, but it can't touch an exchange because there are no keys. Full instructions arrive in Phase 7.

## What would be required before ever going live
This project doesn't go live. If you ever decided to, this is the minimum, and it means changing the hard rules on purpose, not by accident:

1. **Months of paper trading first.** The live strategy must have passed every promotion rule and run in dry-run long enough to see different market moods. Its dry-run results should roughly match its backtest.
2. **Licensed exchange only.** Use a platform that is legally allowed to serve you in your country (see the Pakistan note below).
3. **Trade-only API key.**
   - Enable *spot trading* only.
   - **Withdrawals disabled.** A stolen key then can't move funds out.
   - No futures or margin permission.
4. **IP whitelist on the key.** It only works from your own machine's or server's IP address.
5. **Tiny amounts.** Start with money you can afford to lose completely. Scale up only after live results match paper results for a long time.
6. **Keys live outside git,** for example in a password manager or a secrets file with strict permissions. Rotate them regularly and revoke them at once if anything looks wrong.
7. **A kill switch and monitoring.** Know how to stop the bot and cancel orders from your phone, and set alerts for errors and drawdown.
8. **A separate, reviewed live config.** Never reuse this lab's configs. The safety check would (correctly) refuse them anyway.

### Pakistan note
You are in Pakistan. Live crypto trading would have to follow the **Virtual Assets Act 2026** and use a platform licensed by the **Pakistan Virtual Assets Regulatory Authority (PVARA)**. Exact licensing rules and the list of licensed platforms will be researched from official sources and added here in Phase 8. Rules in this area change quickly, so always check the current official PVARA guidance before acting.
